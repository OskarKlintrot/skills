# Addy lifecycle

Use the user's request as the workflow goal and start the `addy-lifecycle`
dynamic workflow with `{ "goal": "<user request>" }`.

The workflow owns the complete lifecycle, including requirements clarification,
specification, planning, implementation, verification, review and launch
readiness. Do not prepare artifacts, conduct a separate interview, or perform
workflow phases in this conversation before starting it. Do not require any
other installed skill for the workflow to run.

If the dynamic workflow is unavailable, report that limitation rather than
substituting another workflow.
